# 麦门寻宝局 Skill

这个 Skill 把用户的预算、场景、心情和可选偏好转换为三条推荐路线：稳妥之选、新鲜尝试、预算挑战。趣味称号只能作为娱乐内容，必须标记为趣味测试，不代表麦当劳官方人格评估。

## 输入

- `budget`：人民币预算，网页支持 1–500 元，最多两位小数；Skill 可以按用户实际预算计算。
- `scene`：早餐、午餐、下午茶或夜宵。
- `mood`：想吃得满足、想省钱、想尝鲜或今天有点累。
- `preferences`：可选的鸡肉、汉堡、饮品、薯条等偏好。
- 真实查询需要门店或地址上下文时，先向用户收集 MCP 工具 schema 要求的字段。

## MCP 调用策略

1. 确认 Token 仅在服务端环境变量中，并连接 `https://mcp.mcd.cn` 的 Streamable HTTP 服务，使用 `Authorization: Bearer <MCD_MCP_TOKEN>`。
2. 先执行 `initialize`，再执行 `tools/list`，以服务器当前返回的 JSON Schema 为准。
3. 查询菜单时使用官方工具 `query-meals`；需要餐品组成时使用 `query-meal-detail`；需要价格时使用 `calculate-price`。可用门店上下文用 `query-nearby-stores` 获取。
4. 每次 `tools/call` 先按返回 schema 校验参数。工具名称、必填字段、枚举值和返回字段都不能自行猜测。
5. 组合中的餐品编码必须来自本次 `query-meals` 或详情结果。价格必须来自同一批商品调用 `calculate-price` 的返回值。

## 结果与异常

- MCP 未配置 Token、认证失败、超时、429、工具缺失或 schema 不匹配时，说明具体状态。询问缺失字段或让用户主动选择演示模式；不把失败自动包装为实时结果。429 与超时停止本次调用，给出稍后重试入口，避免循环重试。
- 演示数据必须加“模拟”或“演示”标记，状态不能显示已连接，不能写成官方价格、优惠、营养或库存。
- 没有成功的 `calculate-price` 返回时，价格文案只能是“待验证”，不能使用“已验证”。
- 不执行创建订单、取消订单、领券或抽奖等有副作用操作，除非用户明确授权且产品单独实现确认步骤。

## 预算和推荐验证

内部用整数分求和，禁止把元和分混用。先从当前菜单筛选最多三件、每种一份的组合；稳妥之选优先偏好和搭配，新鲜尝试优先不同组合，预算挑战优先预算利用率。少于三条有效路线时说明数据不足，不制造餐品凑数。

菜单中价格仅用于筛选；最终必须用同门店、同就餐方式和同一批商品执行 `calculate-price`，采用明确的应付总价（包含接口返回的费用），过滤超预算候选。若工具需要套餐选项先调用详情确定，不能猜默认选项或优惠资格。没有明确金额单位就请求澄清。计价失败或返回结构变化时只报告待核验结果，不能宣布满足预算。

称号来自用户主动表达：选择薯条可得“薯条守护者”，想省钱可得“预算掌控大师”，夜宵可得“深夜能量补给员”。分享内容必须保留趣味测试标记、数据来源、查询时间、餐品、核验价格状态和推荐理由；不能包含 Token、地址或账号数据。当前餐品只代表查询时可售，不能推断未来时段库存。

## 使用示例

用户：`20 元以内，今天有点累，午餐想吃得满足，喜欢鸡肉。`

处理：校验预算与枚举值；查询当前工具 schema；如缺门店则询问门店或地址；调用 `query-meals` 得到真实编码；用三条路线筛选；为每条候选调用 `calculate-price`；只将成功计价且不超过 20 元的组合标记为已核验；生成趣味称号和只含这些返回数据的分享卡。

无 Token 示例：`当前是演示模式，以下餐品和金额为模拟数据，不代表实时菜单或官方价格。你可以配置服务端 MCD_MCP_TOKEN 后重试。`

完整的无 Token 演示路径：用户主动选择演示，并输入 20 元、午餐、想吃得满足、鸡肉；使用独立虚构菜单“金黄鸡肉堡 · 模拟”12 元、“小份快乐薯条 · 模拟”5 元、“清爽气泡饮 · 模拟”3 元，合计 20 元。输出「模拟组合 · 预算利用 100% · 非官方价格 · 趣味测试称号：快乐补给官」。可同时推荐其他明确模拟路线；所有分享卡仍须显著写“模拟数据”，不能用这个示例替代真实菜单。

真实模式输出示例格式（所有括号字段都必须来自工具返回，不是可售数据）：`稳妥之选：[实际餐品名称与编码]；总价：[calculate-price 应付总价及单位]；核验时间：[实际调用时间]；理由：[预算、场景和偏好与本次数据的关系]；状态：本次 MCP 查询与计价成功。` 若缺门店则先回复 `官方 query-meals 要求门店上下文，请提供门店/地址线索；我会按实际 schema 查询可用门店。` 不填入不存在的具体字段名。
